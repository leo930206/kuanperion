# Book task cursor execution boundary

The unpublished BookCombineTask constructor requires the real shared CursorReceipts dependency; Port must report physical cursor emptiness. No fallback or private replacement ledger silently authorizes a move. Initial preflight requires an empty physical cursor before any root/Farming hold. The future native adapter still must independently bind fresh menu/opening/cursor evidence; this abstract task is not that adapter.

Each input, combine, collect or original-book reclaim arms a new cursor stamp alongside its inventory receipt stamp. Advancement requires both the corresponding exact item proof and a newer server-empty receipt for the same world/container/epoch, after that attempt, at most10 seconds old (inclusive). A prior input's cursor, changed scope/epoch, pre-attempt timestamp, over-age receipt or nonempty carried item never proves a later result. Before any next action and final close, the physical and server cursor checks run again.

A pending local prediction may temporarily show a carried item: within the existing task/recovery deadline, it may settle with an actual matching server-empty receipt, but no new move/close/progress occurs meanwhile. A nonempty ready cursor cancels instead. Manual hooks retain ownership priority. Unknown pending input/cursor states are left for manual recovery: no guessed cursor destination, repair, automatic replay or menu close. Only already confirmed original input plus current physical/server-empty cursor can enter bounded owned recovery; recovery needs another fresh cursor proof before closing.

Final-close cursor or view revalidation failure is FAILED, not a skipped close followed by successful Farming resume. Safety-stop exceptions remain visible after revocation. Existing input/source/preview/cost/result/full43/bounded/manual ownership contracts remain required.

Real task/session tests cover physical start/ready denial, missing input/result/recovery cursor proof, stale time, wrong container/epoch, nonempty server evidence, prediction settling, inclusive10-second boundary, uncertain cancellation and cursor drift precisely at final close. Existing positive tests emit explicit simulated server cursor events with their item receipts, never from a getter/tick or solely from predicted cursor emptiness. No production native sender/menu layout/default, Book service/preferences/UI or live server success is introduced. Stable2.0.17/user configuration remain unchanged.
