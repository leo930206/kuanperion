# Book native operation boundary (not a public feature)

`BookMenuController` implements the existing real task Port against pinned Minecraft26.2. It requires an immutable explicit policy, a declared anvil layout, the shared inventory/cursor ledgers, the original session/coordinator and a typed `AnvilSender`. There is no default layout, `/av` assumption, arbitrary command string, runtime service/settings/UI or startup action. Actual current menus, opening permission and live success remain unverified.

## Native effects

- Bind the exact Book root, level object, original pose/look/selected tool/flying state and concrete native container object, not only its numeric ID. Client thread, safe player, empty physical cursor and physical manual-input guards precede effects. A native object replacement with identical title/ID is not owned.
- Before the first move, require all90 opening slots, including empty external roles and player aliases, to match post-request applied server receipts. A separate opening cursor stamp crosses the newly assigned container scope but retains world/clear generation, global receipt revision, timestamp and inclusive10-second age. Pre-request and same-timestamp old packets cannot satisfy it. Subsequent actions retain the task's stricter per-attempt cursor sequence stamps.
- Ready/native-send gates repeat full43 inventory, complete exact menu, item/cost/role/protection, current root, cursor and unchanged pose checks. Hotbar-only slot-derived protection is added to packet snapshots for equality; no metadata/count/identity is ignored and no main/external protection is normalized away.
- Move only the original selected first/second books to empty declared inputs, combine only the exact expected preview with explicit zero cost, collect only the proved expected result, reclaim only known originals before any combine. Unknown/priced external controls refuse input. Pending local predictions remain observable to the task but cannot authorize the next click without matching server evidence.
- Every possibly-sent native exception freezes further actions; no replay, cursor repair, arbitrary destination, forced close or guessed recovery. Revalidate ownership/server evidence at owned close; a terminal failure never arms Farming.

## Controlled main-slot return (replaces the8469514 hotbar restriction)

Result collection and original-book recovery now use explicit PICKUP, not QUICK_MOVE. BookReturnTransfer freezes the exact source book and all43 inventory slots, binds a declared external result/input role and an explicitly empty raw main slot9..35, then requires:

1. Exact external source removal plus the same complete book on the physical cursor and a fresh scoped server-carried receipt.
2. Before deposit, revalidate that prior pickup proof, all43 slots, current owned native menu and the exact empty main target. An armed destination ticket is placement data, not generic button authority.
3. One native left-click deposits only that known own book into that exact target. The native boundary repeats actual cursor identity, concrete canonical player slot/index, empty/active/nonfake/mayPlace/capacity, current screen/menu/thread and nonnested native-input ownership checks.
4. Both active-menu and canonical player destination receipts plus a fresh physical/server empty cursor must confirm the exact gain, with every other inventory slot unchanged. Local prediction or an unchanged sibling's receipt cannot complete it. Direct server fulfillment is accepted only with the same exact final evidence, not assumed.

The original first/second inputs return only to their original emptied raw main slots; a result selects an explicitly empty main slot before pickup. No merge, hotbar target, guessed destination, cursor repair or retry is allowed. Empty hotbar slots remain untouched; all nine hotbar slots no longer need to be occupied. A possibly-sent deposit or manual/ownership/format/clock failure leaves the item/menu for manual handling, never automatic repair/close.

BookCombineTask advances this protocol only through explicit Port.progressReturn calls in its waiting states, after existing context/inventory/deadline guards. Getters remain read-only. The controller revalidates confirmed return proof before replacing it with a second original-book recovery or closing the owned menu. Current Anvil layout/open permission, runtime service/settings/UI and live server validation remain pending; controlled returns do not complete the public Book feature.

## Verification scope

The real production controller is composed with the real task/session/planner and simulated packet ledgers in a headless fixture. It covers the entire opening/input/zero-cost combine/result/close and original recovery paths (including both originals through real controlled deposits), missing receipts, cursor evidence, unknown costs/roles, predicted settling, exact level/container identity, pose/equipment drift, manual/ownership takeover and send uncertainty. Real26.2 ItemStack/Slot fixtures separately verify native projections and packet-vs-hotbar protection. A compiled/linkable native implementation is not a live GUI/server interaction claim. Existing stable2.0.17/user preferences remain unchanged.
