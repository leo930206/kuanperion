# Book task complete-inventory execution boundary

The unpublished BookCombineTask.Port now requires the native BookInventorySnapshot rather than a potentially incomplete map of books. A single expected immutable43-slot baseline advances only after an authorized server-proved input transfer or a confirmed original-book recovery. Every normal ready state requires the complete baseline unchanged. A pending input may change only its exact source to canonical empty; unrelated main items, hotbar, armor/offhand/body/saddle and metadata changes stop before another action. The visible menu must agree with all36 canonical player inventory slots.

An input needs both its container source/destination receipts and the same fresh canonical window0 source receipt, each matching the physical snapshot. A result or recovery may create exactly one expected main-inventory book or increment one compatible stack by one. Every other slot must remain unchanged; the changed destination needs its own matching server receipt. An unchanged identical sibling receipt, unrelated gain/loss, protected destination or altered stack identity cannot validate a predicted result. Empty-source and exact metadata/zero-cost/preview/result contracts remain in force.

Observation errors end the original task, but a safety-stop callback exception after terminal revocation remains visible rather than being caught and hidden by a second finish. The internal handle/known-input fields are cleared before the original session finish callback.

Real task/session regression tests demonstrate prior failures at first/second transfer, combine, result and recovery when nonbook or protected inventory changed. Positive cases preserve preexisting unrelated items and compatible output stacks. Missing canonical source proof, borrowed sibling receipts, manual ownership, recovery, unknown outcomes, timeout and positive/ambiguous costs remain covered. Test fixtures now model the actual canonical inventory alias accompanying a server-applied container source update; no client prediction is promoted to a receipt.

This is an execution-protocol dependency, not a native click driver or complete public feature. There is still no default live anvil layout/open command, Book runtime caller/service/settings/UI, cursor integration or claimed live server success. Stable2.0.17, user preferences and existing native action permissions remain unchanged.
