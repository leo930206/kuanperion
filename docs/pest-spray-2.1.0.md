## Implemented safety model

- Exact explicitly configured material ID/native ID/name, and a unique catalog name-to-ID match. Every copy of that ID is checked across all43 slots; hotbar/equipment/protected/UUID/component-variant copies block the action because the server chooses the consumption source.
- Exactly one matching source-ID tool in the hotbar with known matching selection. No implicit material change, inventory movement, buying or Coins authorization.
- One independent PEST_SPRAY root requires the existing manually armed Farming session. Pause its original inputs and allow bounded natural settling; freeze original tool/look, settled position, level/player identity and position-receipt epoch/sequence. Any correction, handover, foreign screen, identity/pose change or expiry stops. No movement/velocity/flight/look writes.
- Private one-use kind-scoped EQUIP/USE/RESTORE actions. The native edge rechecks actual all43/cursor/pose/Tab/thread/identity/current root after the fallible claim and before any effect. It calls ordinary gameMode.useItem(MAIN_HAND), not Minecraft.startUseItem or a blanket manual-world-input exemption. Only the hotbar selection is written/restored.
- Reserve the full provisional five-item ceiling before use, never refund it on an uncertain outcome. Exactly one native use; possible-send exceptions never retry or repair.
- Completion needs post-claim GAME acknowledgement naming the same plot, a new matching ACTIVE Tab observation, and new applied window-0 receipts for every changed authorized inventory stack. A predicted decrement, native return, chat alone or unknown field cannot substitute. Full43 settled verification also applies when restoring the already-selected original slot would otherwise be a no-op.
- Reentrant failed preflight/post-acquire readers cannot cancel a newer accepted generation; revocation during data demand cannot strand ACQUIRING. Owned lookup disposal releases only its exact root and does not leak transport ownership on a close error. No method writes Farming=true.

## Applied Tab refresh checkpoint (2026-10-30, still unexposed)

Cached text alone no longer supplies NONE acquisition or ACTIVE completion. PestSprayTabReceipts retains only one immutable bounded observation of the unique Pests-scoped Spray row. The native observer runs after pinned26.2 handlePlayerInfoUpdate, requires UPDATE_DISPLAY_NAME for that actual listed PlayerInfo identity, a unique matching UUID entry and equal fully applied Component, and binds level/player/world, local non-Barn plot and server-position epoch/sequence. Unknown IDs, non-display/unrelated rows, duplicate entries, unapplied lookalikes, recreated rows or a different connection cannot mint a usable receipt. Plain polling cannot refresh its timestamp. Unknown/ambiguous sections remain unknown. GardenTabReader keeps its original ordering/text behavior while exposing the same ordered row identities to this observer.

Task acquisition/use require a fresh matching NONE fact. USE claims freeze its actual receipt; success additionally requires a same-epoch higher-sequence ACTIVE observation after that claim, plus the existing GAME and applied inventory-delta proof. The final actual/no-op restore also rechecks freshness. A two-second freshness ceiling is a provisional local fail-closed limit, NOT a current Hypixel cadence assertion. Expired/missing ACTIVE waits only within the original bounded outcome window; it never resends or repairs. World/shutdown clear the observation ledger. No service or automatic controller is constructed, and the observer itself only reads/caches facts: no keys, item use, command, movement, file/network access or Farm rearm.

RED reproduced old completion from cached ACTIVE plus the other receipts, with no applied Tab update. Model tests now reject that path and cover stale NONE, plot handover, expiry/recovery, epoch invalidation and final restore (including a separately reproduced post-native proof revocation). Controlled native-wrapper tests execute the actual adapter/effect bodies and the real ledger/task; pinned vanilla bytecode shows known-ID action application and the display setter. These are not transformed-Mixin, real-client or current-server acceptance. Local plot binding does not by itself prove server-to-plot attribution for a delayed Tab packet. Fresh packet cadence/grammar/plot semantics and the new hook's applied-Mixin startup still need batch acceptance.
