## Implemented safety model

- Exact explicitly configured material ID/native ID/name, and a unique catalog name-to-ID match. Every copy of that ID is checked across all43 slots; hotbar/equipment/protected/UUID/component-variant copies block the action because the server chooses the consumption source.
- Exactly one matching source-ID tool in the hotbar with known selection. The four-argument selected-only task never changes it; the explicit cursor-ledger/selection-port composition may select the configured material through the separately guarded child. No inventory movement, buying or Coins authorization.
- One independent PEST_SPRAY root requires the existing manually armed Farming session. Pause its original inputs and allow bounded natural settling; freeze original tool/look, settled position, level/player identity and position-receipt epoch/sequence. Any correction, handover, foreign screen, identity/pose change or expiry stops. No movement/velocity/flight/look writes.
- Private one-use kind-scoped EQUIP/USE/RESTORE actions. The native edge rechecks actual all43/cursor/pose/Tab/thread/identity/current root after the fallible claim and before any effect. It calls ordinary gameMode.useItem(MAIN_HAND), not Minecraft.startUseItem or a blanket manual-world-input exemption. Only the hotbar selection is written/restored.
- Reserve the full provisional five-item ceiling before use, never refund it on an uncertain outcome. Exactly one native use; possible-send exceptions never retry or repair.
- Completion needs post-claim GAME acknowledgement naming the same plot, a new matching ACTIVE Tab observation, and new applied window-0 receipts for every changed authorized inventory stack. A predicted decrement, native return, chat alone or unknown field cannot substitute. Full43 settled verification also applies when restoring the already-selected original slot would otherwise be a no-op.
- Reentrant failed preflight/post-acquire readers cannot cancel a newer accepted generation; revocation during data demand cannot strand ACQUIRING. Owned lookup disposal releases only its exact root and does not leak transport ownership on a close error. No method writes Farming=true.

## Source-style selection composition (2026-10-30, still unexposed)

The five-argument spray task uses the SAME held PEST_SPRAY root for settle/equip → optional material selection → fresh NONE revalidation → one spray → exact original-slot restore. Preparing a plan with a known wrong/None selection is not USE authority: an exact selected plan must be rebuilt after the child completes. The selected-only constructor stays deliberately constrained. The overall lease is35s; selection is bounded to10s, and after owned GUI close the parent waits at most3s for a genuinely fresh NONE without repeating selection or use.

Selection requires a unique source-style exact material role in a complete9..54-slot named Sprayonator container, configured canonical native icon identity, no UUID/protection, an exact Click to select hint and no cost/price/currency/transfer/selected contradiction. Titles/hints/icon grammar are PROVISIONAL. Before clicking, all menu slots and empty cursor need applied opening receipts. Afterward, the exact source-prefix GAME acknowledgement, canonical window0 raw36+slot AND active-container hotbar metadata receipts, fresh empty cursor, unchanged all43 except the selected tool, and fresh receipts for changed menu slots must agree. A native invariant masks ONLY the unique source-known Selected Material lore line; CUSTOM_DATA, UUID, names, other components and all other lore remain exact. Any unverified server selection-NBT change fails closed rather than silently broadening the whitelist.

The opener synchronizes the authorized selected slot via the pinned private vanilla ensureHasSentCarriedItem invoker, then performs only the normal MISS air-swing subset. It refuses blocks/entities, cooldown, busy hands, spectator/destroying, disabled/cannot-attack/piercing items, physical takeover and all late identity/pose/inventory changes. There is no startAttack/world-input exemption, raw packet, guessed rotation/movement, key write or retry. This subset's ability to open the current Hypixel GUI is NOT yet established. Native menu input is available only through a private original-root child action; generic carried-item senders remain unchanged. Only a proven acknowledged still-owned menu may be locally closed; unsolicited/server-auto-close paths stop safely rather than guessing ownership or repairing the cursor.

Reentrant child cancellation after carried-slot synchronization was reproduced against the previously built child bytecode (cancelled but one swing still sent), then fixed by checking the private action's live pending/sending claim at the last physical boundary. Tests also cover wrong-world frame binding, source-prefix case with exact material identity, deferred post-selection Tab refresh, reentrant startup/new generations, and terminal native world/player/Tab reference disposal including rejected acquisition. The headless invariant fixture initially used an unbound registry default stack; it now uses the project's explicit Holder.direct fixture, without changing production guards. Native-wrapper AIR flags likewise now correctly represent false while a menu is open; setup errors are not claimed as production regressions.

The selection/parent path is implemented and testable, but this is NOT a finished AutoSprayonator service or current-server acceptance. Persisted independent consent/UI, original-root stock buying, dispatch/lifecycle integration, applied-Mixin startup and ONE final batch covering titles/hints/cursor/close/NBT/nozzle/base/Sacks/Tab cadence/plot attribution remain gated.
