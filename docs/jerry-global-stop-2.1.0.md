# Jerry global stop — 2.1.0 development

The existing Jerry stop-actions switch now applies even with Farming/Mining/recovery off. It suspends all six currently executable new services: Pest, Greenhouse, Composter, Auto Sell, Junk and the separately leased Stash. Standalone/manual tasks are cancelled through their existing guarded cleanup; enabled but idle threshold/interval/signal jobs are suspended too, so a later due timer or Stash message cannot silently restart work.

Ordinary lifecycle cancellation still does not disable idle automation. The new explicit safety suspension is a separate operation. Idle suspension changes no saved preferences: the latest external settings remain byte-identical, while the effective UI toggle is off for this session. Active task cancellation keeps its existing failure/stop behavior, including persistent disabling where already implemented. Only an explicit per-feature enable acknowledges an automatic suspension. An explicit manual one-shot remains possible without re-arming auto. No Farming session is ever started or resumed by this operation.

The legacy Jerry handler still records home first if configured, stops legacy actions before preparing its beam, and retains the exact two home-notification formats and independent notification channels. Only when Jerry stop is on does it then suspend the new services. With stop off, trusted automatic sethome still preserves the held task and Farming; manual commands retain priority. The suspension itself does not close a user-owned GUI or repair a cursor/inventory.

Actual service tests cover idle enabled preferences, no later automatic dispatch and explicit re-enable; Stash additionally tests active command-lease cancellation without Farming and explicit manual one-shots. Actual legacy/bridge method bodies are composed with real AutomationSession/FarmingHandoff for all six standalone/manual actors, idle timers, three held-Farm actors, both stop states and chat settings. A negative mutation reverting to a legacy-Farm-only stop must fail. Native offline bridge checks verify no lease/preferences side effects.

Future executable Visitor/Supercraft/Pet Sell must extend the six-service source/behavior matrix before release; a source guard intentionally fails if a newly implemented feature is omitted. This is not live server validation or a claim that the entire seven-stage upgrade is finished.
